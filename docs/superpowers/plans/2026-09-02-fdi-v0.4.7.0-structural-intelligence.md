# FDI v0.4.7.0 Structural Intelligence Integration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Integrate provider-independent, bounded Structural Intelligence into FDI Maintain Product and Develop Feature workflows without changing HERM-211 authority or allowing graph-derived current Feature truth.

**Architecture:** Add an FDI-owned Structural Intelligence Runtime beside durable Layer 2 Product Intelligence. Grafel is isolated behind `CodeIntelligenceProvider`; normalized structural observations can generate bounded discovery hints and maintenance signals, while PA-03 identity grounding and current feature-specific Evidence preserve canonical Feature truth boundaries.

**Tech Stack:** Python 3, pytest, JSON Schema/JSON artifacts, deterministic ZIP packager.

**Spec:** `00-product/FDI-MVP-v0.4.7.0-STRUCTURAL-INTELLIGENCE-INTEGRATION.md`

## Global Constraints

- Do not modify Layer 1 T1–T4 governing transitions.
- Do not add or rename HERM-211 six helper contracts.
- Do not change `SPEC_READY | BLOCKED` as the sole canonical T2 gate.
- Grafel/provider schema and tool names must not leak into governing FDI contracts.
- Structural queries must be source-pinned and bounded.
- Structural observations/hints cannot establish `CONFIRMED`, `EXCLUDED`, `ChangeSurfaceSet`, or `SPEC_READY`.
- Structural candidates must be grounded through PA-03 identity and retain `basis=LAYER2_PA03`.
- F001 ablation semantics must be frozen before any F001 execution.
